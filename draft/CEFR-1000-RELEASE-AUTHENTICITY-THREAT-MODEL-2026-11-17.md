## Confirmed gaps in current preflight implementation

1. **Invented evidence passes schema checks.** The adversarial test explicitly documents this as an expected failure. An `approved` string plus nonempty reviewer/source/date strings is not independent approval. A GitHub actor who can edit JSON could impersonate every reviewer.
2. **Review IDs are not a strict set match.** Code checks only that `len(review_by_id) == len(entries)`; it does not assert that both ID sets are identical. A stray review can replace one missing review without satisfying all records, although the per-entry missing-review check catches that particular case. Duplicate *manifest* entry IDs are not explicitly rejected, so two distinct entries can share one review record.
3. **Audio records are not verified against files.** The `sha256` field is merely checked for nonempty text; there is no 64-hex validation, file existence, digest calculation, codec check, expected spoken text or evidence that a human listened.
4. **QA evidence is not independently validated.** Nonempty `evidence_url`, `verified_by`, `verified_at` and `passed: true` cannot establish a physical iPhone Safari test, GitHub Pages hosting clearance or real production deployment.
5. **Sources are not exact-sense validated.** Nonempty `source_url` and `observed_on` fields do not prove a URL resolves, that a reputable source assigns that specific sense to the requested CEFR level, or that Myanmar and example usage were independently checked.
6. **No trusted separation of duties.** The script does not enforce reviewer identity, reviewer independence from author, immutable review evidence, or an approval tied cryptographically to the exact approved manifest digest.
7. **Production deployment is circular.** A pre-deployment JSON `production_deployment.passed` cannot prove deployment that has not happened. Use separate *prelaunch* and *postdeployment* gates; postdeployment checks must not retroactively excuse prelaunch omissions.

## Required repair sequence (no bypass)

- Add explicit manifest-entry ID uniqueness and exact review-ID-set checks; reject non-string/blank IDs, malformed fields, and unknown levels before release.
- Split structural checks from evidence authenticity: use a trusted, independently administered reviewer-signoff store, bound to exact entry/content digest and dated source snapshots; reject unsigned or self-signed evidence. A reviewer must assess English, fluent Myanmar, example grammar, exact-sense CEFR, and pronunciation separately. Human signoff cannot be generated by the assistant.
- Bind each George/Emma × headword/example audio record to a real on-disk asset, compute and compare SHA-256, verify decodability and duration, and require external listening records tied to that asset digest. Four audio items per entry = **4,000** recordings and independently documented listening outcomes for the final 1,000 entries.
- Record physical-device iPhone Safari model/iOS/browser, timestamp, test cases, screenshots or video, tester identity and immutable evidence reference. Simulators do not satisfy the physical-device requirement.
- Independently validate GitHub Pages build size/limits, published paths, privacy and preserved production 54 lessons, IELTS bank and existing George/Emma audio. Keep publishing permissions isolated from staging validation.
- Permit deployment only after all prelaunch gates pass. Afterwards verify live URLs and content hashes against the approved manifest, then record production deployment evidence. Notify the user only when every gate including postdeployment verification is truly complete.
